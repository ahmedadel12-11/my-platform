# منصة مستر أحمد عادل — نسخة Cloudflare Pages + D1

هذه حزمة تطبيق ويب Full-stack مبدئية قابلة للنشر، وليست مجرد تصميم ثابت. تشمل واجهة عربية RTL وواجهات Pages Functions وقاعدة D1.

## ما الذي يعمل في هذه النسخة؟
- دخول المدرّس بكلمة مرور إدارية محفوظة كـ Cloudflare Secret، وجلسة Cookie آمنة HttpOnly.
- دخول الطالب بكود ورقم سري مستقلين، مع تخزين تجزئة PBKDF2 للرقم السري وليس الرقم نفسه.
- إنشاء الطلاب والمجموعات، وربط الطالب بمجموعة، وتعديل بيانات الطالب وحذفه.
- توليد كود ورقم سري عشوائيين آمنين عند إنشاء الطالب، ويظهران مرة واحدة للمدرس.
- تسجيل الحضور/الغياب/التأخير بتاريخ الحصة، وتحديث السجل عند إعادة تسجيل التاريخ نفسه.
- تنبيه عند 3 مرات غياب وتحذير عند تجاوز 3 مرات.
- إنشاء امتحانات ورصد الدرجات مع التحقق من الدرجة النهائية والمرحلة، وحساب النسبة المئوية.
- إعلانات عامة أو موجهة لمرحلة محددة.
- لوحة الطالب تعرض بياناته ودرجاته وحضوره وإعلانات مرحلته فقط.
- تنزيل كشوف CSV بترميز UTF-8 BOM لتفتح في Excel، والطباعة إلى PDF من المتصفح. أضفنا أيضاً ترويسات حماية للمتصفح وسياسة محتوى تمنع تحميل سكربتات خارجية.
- حماية من عرض بيانات الطلاب للطلاب الآخرين عبر التحقق من جلسة الطالب في الخادم.

## ما الذي يحتاج ربطاً خارجياً أو استكمالاً؟
- لا يوجد إرسال SMS/WhatsApp آلي لولي الأمر؛ تظهر أرقام أولياء الأمور للمدرس في تنبيهات الغياب، وإرسال الرسائل يحتاج مزود رسائل وربطاً وموافقة مناسبة.
- PDF الحالي يتم عبر نافذة الطباعة في الجهاز، وليس توليد PDF خادمي مستقل.
- لا يوجد استيراد جماعي من Excel، أو إعادة تعيين PIN، أو سجل تدقيق شامل في هذه النسخة.
- يلزم اختبار قبول نهائي على حساب Cloudflare الفعلي بعد إنشاء D1 وضبط الأسرار؛ لم يتم نشر المنصة من هذه الحزمة ولا يوجد رابط إنتاج بعد.

## متطلبات النشر
- حساب Cloudflare.
- حساب GitHub (الطريقة الأسهل من الهاتف).
- قاعدة Cloudflare D1 مجانية ضمن حدود الخطة المجانية الحالية. راجع حدود Cloudflare قبل اعتمادها لعدد الطلاب واستخدامك.
- لا تضع كلمة مرور المدرس أو بيانات الطلاب في GitHub.

## النشر من الهاتف (GitHub + Cloudflare Pages)
> تنبيه مهم: لأن التطبيق يستخدم Pages Functions، لا يكفي رفع مجلد `public` بالسحب والإفلات من لوحة Pages؛ Cloudflare يوضح أن Direct Upload من لوحة التحكم لا يدعم Functions. استخدم Git integration.

1. نزّل ZIP وفك ضغطه على الهاتف.
2. افتح GitHub وأنشئ مستودعاً جديداً باسم `ahmed-adel-platform`، واجعله **Private**.
3. ارفع جميع محتويات المجلد إلى جذر المستودع، مع الحفاظ على المجلدات `functions` و`migrations` و`public` وملف `wrangler.toml`.
4. افتح Cloudflare Dashboard ثم Workers & Pages → Create application → Pages → Connect to Git، واختر المستودع.
5. اسم المشروع: `ahmed-adel-platform`. إعدادات البناء:
   - Framework preset: None
   - Build command: اتركه فارغاً
   - Build output directory: `public`
   - Root directory: `/`
6. أنشئ قاعدة بيانات D1 من Workers & Pages → D1 SQL Database → Create database، وسمّها `ahmed-adel-platform`.
7. انسخ Database ID من صفحة قاعدة البيانات. افتح `wrangler.toml` في GitHub وعدّل:
   `REPLACE_WITH_YOUR_D1_DATABASE_ID`
   إلى Database ID الحقيقي ثم احفظ التعديل.
8. من Cloudflare افتح D1 → قاعدة البيانات → Console، والصق محتوى الملف `migrations/0001_initial.sql` كاملاً ثم نفّذه مرة واحدة.
9. في مشروع Pages افتح Settings → Bindings → Add → D1 database:
   - Variable name: `DB`
   - اختر قاعدة `ahmed-adel-platform`
   ثم احفظ وأعد نشر المشروع.
10. افتح Settings → Variables and Secrets (أو Environment variables حسب واجهة الحساب) وأضف Secret:
    - Name: `ADMIN_PASSWORD`
    - Value: كلمة مرور إدارية قوية وفريدة، لا تشاركها ولا تضعها في ملفات المشروع.
    احفظ ثم أعد نشر المشروع حتى يصل السر إلى Functions.
11. افتح رابط `*.pages.dev` الذي يظهره Cloudflare. جرّب `/api/health`؛ المتوقع `{"ok":true,...}`. ثم سجّل دخول المدرس.
12. أنشئ مجموعة، ثم طالباً تجريبياً، وسجّل حضوراً وامتحاناً ودرجة وإعلاناً. اختبر دخول الطالب بالكود والـPIN اللذين ظهرا مرة واحدة.

## ملاحظات مهمة عن إعداد D1
ملف `wrangler.toml` يحتوي اسم قاعدة البيانات ومعرّفاً placeholder. عند استخدام لوحة Cloudflare، يجب أيضاً إضافة Binding باسم `DB` من إعدادات Pages كما في الخطوات. لا تنشر قبل استبدال الـ placeholder بمعرّف قاعدة البيانات الفعلي.
يمكن لاحقاً استخدام Wrangler من كمبيوتر أو Termux لتنفيذ migrations آلياً، لكن الخطوات أعلاه تتجنب الحاجة لسطر الأوامر.

## الخصوصية والأمان
- استخدم مستودع GitHub خاصاً.
- لا ترفع بيانات حقيقية أو كشوف درجات إلى GitHub.
- استخدم أسماء الطلاب والحد الأدنى من بيانات ولي الأمر الضرورية فقط، واحصل على الموافقات اللازمة من أولياء الأمور/المسؤولين قبل معالجة بيانات القُصّر.
- اجعل كلمة مرور المدرس طويلة وفريدة، ولا ترسلها للطلاب.
- الرقم السري للطالب لا يُعرض مجدداً بعد إنشاء الحساب. احتفظ به في قناة آمنة. لا تطلب من الطلاب إرسال كلمات المرور في مجموعات عامة.
- لا تستخدم المنصة وحدها كسجل رسمي قبل إجراء اختبارات تشغيل ونسخ احتياطي منتظم.
- أضف سياسة خصوصية ووسيلة تواصل مع مسؤول المنصة قبل استقبال طلاب حقيقيين.

## الملفات
- `public/`: واجهة الموقع.
- `functions/api/[[path]].js`: API وعمليات المصادقة والصلاحيات.
- `migrations/0001_initial.sql`: مخطط قاعدة البيانات.
- `wrangler.toml`: إعداد Pages وD1.
- `docs/TEST-REPORT.md`: نتائج الاختبارات المحلية وحدودها.
